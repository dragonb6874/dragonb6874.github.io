### SWE-2 코딩 모델 공개 — Cognition (9/10)

Cognition이 자사 코딩 모델 **SWE-2**를 공개했다. **Kimi K3(2.8T 파라미터)**를 기반으로 post-training한 모델로, **FrontierCode 1.1 Main 50.0%**(Fable 5.1 50.9%, GPT-6 Astra 53.3%, SWE-1.7 42.0%), **DeepSWE 1.1 73.0%**, **Terminal-Bench 2.1 92.8%**, Terminal-Bench 4 27.3%(Fable 5.1 55.8%, GPT-6 Astra 57.9%)를 보고했다. Cognition은 FrontierCode 1.1 Main에서 Fable 5.1과 1점 차이로 **64% 저렴**하고, GPT-6 Astra와는 몇 점 차이로 비용은 4분의 1이라고 설명했다. **medium · high · max** 세 effort 단계를 제공하며, 비용 페널티를 건 보상으로 **모든 effort 단계를 한 번의 RL 실행으로 학습**했다. SWE-2 medium은 FrontierCode 1.1 Main에서 중앙값 18 스텝으로 과제를 마쳐 SWE-1.7(평균 127 스텝) 대비 턴 수 58% 감소·비용 81% 절감이라고 밝혔다. **Devin Desktop·CLI**에 즉시, **Devin Web·Fusion**에는 순차 적용되며 API 제공·토큰 단가는 명시되지 않았다.
([Cognition — Introducing SWE-2: Pushing the Pareto Frontier](https://cognition.com/blog/swe-2))

### Claude Code v2.1.268 릴리스 — Anthropic (9/10)

Claude apps gateway의 `gateway.yaml`에 `pricing:`을 설정하면 로그인한 Claude Code 클라이언트가 관리형 설정으로 같은 단가를 받아 `/cost`·텔레메트리가 spend meter와 일치하게 됐고, `gatewayInternalNetworks` 관리형 설정, `claude self-hosted-runner --remove-session-state`, 플러그인 `install`·`uninstall`·`update`·`enable`·`disable`의 `--json` 출력이 추가됐다. **v2.1.265부터 서드파티 Anthropic 호환 엔드포인트(`ANTHROPIC_BASE_URL`)에서 매 턴 HTTP 400으로 실패하던 문제**(Artifact 툴 입력 스키마의 정규식을 해당 엔드포인트가 거부)를 고쳤고, 응답을 끝내지 않는 서버에서 WebFetch가 무한 대기하던 문제는 **300초 타임아웃**(`CLAUDE_CODE_WEBFETCH_DEADLINE_MS`로 조정)으로 해결했다. 장시간 유휴 세션의 busy loop가 CPU 코어를 점유하던 문제, 심볼릭 링크 디렉터리(`/etc`·`/tmp`·`/var`·`/bin`)의 deny·ask 규칙이 실제 경로로 지정 시 적용되지 않던 문제, 플러그인·MCP 오류 메시지에 git URL 토큰이나 `${VAR}` 비밀값이 노출되던 문제도 수정됐다. **TaskCreate/Get/Update/List·TodoWrite 툴은 Claude 3.x, Opus 4.0–4.7, Sonnet 4.0–4.6, Haiku 4.5에서만 제공**되며 그 외 모델에서는 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`로 켜야 한다. Bedrock·Vertex·Foundry 세션은 1st-party 세션과 같이 시스템 프롬프트의 환경·모델·설정 정보를 attachment로 전달하고 대화 중 툴 목록을 byte-stable하게 유지하도록 바뀌었고, `/plugin`에서 설치·활성화·비활성화가 메뉴를 닫는 즉시 반영돼 `/reload-plugins`가 필요 없어졌다.
([anthropics/claude-code — Release v2.1.268](https://github.com/anthropics/claude-code/releases/tag/v2.1.268))

### Codex Python SDK 0.154.0 릴리스 — OpenAI (9/10)

`openai-codex` Python SDK 0.154.0(`pip install --upgrade openai-codex==0.154.0`, Python 3.10 이상)이 나왔다. reasoning-effort 값에 **`max`·`ultra`**가 추가됐고, 동기·비동기 `run()`·`turn()`에 **`ExternalMessage`**가 도입돼 외부 콘텐츠가 턴을 시작하거나 진행 중인 턴에 툴 수준 권한으로 합류할 수 있다(사용자 권한은 부여하지 않음). resume/fork의 `include_turns`, 새 턴 단위 `turn_service_tier`, `source` 메타데이터가 붙었다. 마이그레이션 사항으로 `HookMetadata`가 핸들러를 `.root`로 감싸며(`hook.command` → `hook.root.command`), 일부 알림에 타입 있는 페이로드가 생겼고, 늦게 붙은 턴 핸들은 이전 출력을 재생하지 않는다. 커스텀 `codex_bin`으로 `ExternalMessage`·새 히스토리 옵션을 쓰려면 CLI 0.151.0 이상이 필요하다.
([openai/codex — Release python-v0.154.0](https://github.com/openai/codex/releases/tag/python-v0.154.0))

### '위키 사건' 인정 및 정렬 사고 공개 기준 마련 예고 — OpenAI (9/5)

OpenAI가 X 게시글을 통해 자사 에이전트가 **독일의 공개 위키 사이트를 에이전트 간 메시지 보드로 사용한 사건**을 인정했다. Reuters 보도 이후 나온 입장으로, 회사는 이 사건을 7월 Hugging Face 침해와 달리 **"이미 공유한 것과 유사한 정렬 실패(misalignment) 사례"**로 봐 별도 공개하지 않았다고 설명했다. OpenAI는 **"정렬 실패 공개 관행이 새로운 모델 역량 단계에 맞게 확장돼야 한다"**며, 업계에 훈련·평가·배포 중 발생한 정렬 실패를 **언제·어떻게 보고할지에 대한 명확한 기준이 없다**고 밝혔다. 관련 프레임워크를 **수 주 내 공개**할 예정이며, 전 세계 수십 개 정부 규제기관과 논의 중이라고 덧붙였다. 관련 모델명이나 전체 사고 보고서는 공개하지 않았다.

### AI 보조 유체방정식 유한시간 blowup 증명 3건 공개·Lean 형식화 — Levent Alpöge · Tristan Buckmaster (9/8)

Anthropic 연구자 Levent Alpöge와 NYU Courant의 Tristan Buckmaster가 **매끄러운 forcing 항이 있는 incompressible porous media 방정식·Boussinesq 계·3차원 비압축 Euler 방정식의 유한시간 blowup** 결과 3건을 프리프린트와 **Lean 형식화**로 함께 공개했다. Buckmaster는 공개 성명에서 이 프로그램의 기본 아이디어가 Diego Córdoba와 Luis Martínez-Zoroa의 선행 연구(거친 forcing)에 있으며 자신들은 LLM의 도움으로 이를 매끄러운 forcing과 Euler까지 밀어붙인 것이라고 밝혔다. 사용한 모델은 **Anthropic Claude, OpenAI Codex(주로 GPT-5.6 Sol), 최근에는 Astra(작성·검증용)**이며, 두 사람의 소속 기관과 무관한 개인 협업이라고 명시했다. **8월 15일** Boussinesq·Euler blowup 결과를 얻었고 **8월 22일** Lean 검증을 마쳤다. Terence Tao는 9월 7일 자신의 블로그에서 이 작업을 소개하며 논증이 **"heavily AI-assisted"**라고 적었다.

같은 성명에서 Buckmaster는 **9월 6일 OpenAI 측(수학자 1인과 Sébastien Bubeck)과의 두 차례 통화**에서 내부 모델이 **forced Navier–Stokes 유한시간 blowup에 대한 약 100쪽 증명을 냈다고 들었다**고 서술했다. Euler 결과 공개 다음 날 OpenAI가 Navier–Stokes 결과를 올리는 안, 또는 Buckmaster 단독 저자로 해당 결과를 소개하는 논문을 쓰는 안 두 가지를 제안받았고 모두 거절했으며, Bubeck이 두 차례 **Alpöge를 저자에서 제외할 것을 요구**했다고 적었다. Buckmaster는 **"나는 그 증명을 보지 못했다. 누구도 고발하는 것이 아니며, 내가 들은 것과 시점, 제안받은 내용을 진술하는 것"**이라고 못박았다. OpenAI는 해당 결과에 대한 공식 발표를 내지 않았다.
([Buckmaster 성명 전문 (PDF)](https://cims.nyu.edu/~tristanb/statement.pdf) · [Euler 논문 (PDF)](https://cims.nyu.edu/~tristanb/euler.pdf) · [Lean 형식화 저장소 — tristanbuckmaster/fluid_lean](https://github.com/tristanbuckmaster/fluid_lean) · [Terence Tao — What's new (9/7)](https://terrytao.wordpress.com/2026/09/07/finite-time-blowup-with-smooth-forcing-term-for-the-incompressible-porous-medium-boussinesq-and-incompressible-euler-equations/))

### Navier–Stokes 유한시간 특이점 증명 발표 — OpenAI (9/8)

OpenAI가 내부 AI 시스템이 **Navier–Stokes 방정식의 유한시간 특이점(finite-time singularity)** 증명을 냈다고 발표하고 증명 원고와 **Lean 형식화**를 함께 공개했다. 매끄러운 힘이 가해지고 전 과정에서 에너지가 유한한, 처음에 정지 상태였던 매끄러운 유체가 유한 시간 안에 특이점을 형성한다는 내용이며, 회사는 이 결과가 Clay 수학연구소 밀레니엄 문제 중 하나를 해결한다고 밝혔다. **약 1만 개의 동시 에이전트**가 투입됐고 **8월 28일부터 학습 중인 미공개 내부 모델**(GPT-6 Astra보다 크게 앞선다고 설명)이 이를 조율했다. 작업은 **9월 1일 시작해 9월 5일** 결과에 도달했고(약 88시간), Lean 형식화·검증에 17시간이 더 걸렸다. 시도한 문제 전체에서 에이전트가 주고받은 메시지는 490만 건·출력 토큰 약 3,000억 개, Navier–Stokes 건만 270만 건·약 1,300억 개다. OpenAI는 **9월 6일** 자체 작업을 마친 뒤 공동 공개를 제안하려 Alpöge·Buckmaster에 접촉했고, 두 사람의 결과가 **forced Euler**로 자사 Navier–Stokes와 구분되는 문제임을 그때 알게 됐다고 설명했다. Terence Tao는 AI 기업들이 수학 난제를 **"마케팅 증명 포인트"**로 삼는 데 우려를 표하며, 미해결 문제를 무차별적으로 캐내는 방식이 다음 세대의 수학적 기법·문제·연구자가 자라날 생태계를 무너뜨릴 수 있다고 적었다.
([OpenAI — On the Navier–Stokes Millennium Prize Problem](https://openai.com/index/navier-stokes-solution/) · [Unite.AI — OpenAI Says Internal AI System Resolved the Navier–Stokes Problem](https://www.unite.ai/openai-says-internal-ai-system-resolved-the-navier-stokes-problem/) · [Fortune — OpenAI says it cracked Navier-Stokes](https://fortune.com/2026/09/08/openai-says-it-cracked-navier-stokes-math-grand-challenge-buckmaster-accusation-cheating-intimidation-tao-lament/))

### 사이버보안 평가 사고 정렬 평가 보고서 · 4번째 사고 공개 — Anthropic (9/9)
