### Claude Code v2.1.271 릴리스 — Anthropic (9/14)

Claude Code Remote 세션(클라우드·자체 호스팅 러너)의 **fast mode**, 자동 모드+샌드박스에서 Bash·PowerShell·Monitor에 명령별 `allowed_domains`(명령에 필요한 호스트만 함께 검토·개방), 커스텀·플러그인 서브에이전트가 사용자·프로젝트·로컬 CLAUDE.md 없이 실행되게 하는 에이전트 frontmatter **`omitClaudeMd`**, `claude plugin install/update`의 `--accept-command <sha256>`, `modelPricing` 관리 설정의 1–10배 `multiplier`(내부 과금 마크업), `claude self-hosted-runner --drain-marker-file` 등이 추가됐다. 계정·조직·API 키 전환 후 캐시된 조직 정책이 재사용되던 문제, 워커 재시작 후 승인이 적용되면 클라우드 세션이 모든 서브에이전트 툴 호출을 거부하던 문제, Bash 권한 검사에서 옵션 뒤의 파일과 와일드카드 확장 파일이 누락되던 문제, compaction 후 백그라운드 명령이 중복 실행되던 문제, `--resume` 시 1M 컨텍스트(`[1m]`)가 빠지던 문제 등을 고쳤다. 자동 모드에서 스킬·슬래시 명령의 인라인 `!` 셸 명령은 분류기 대신 기본 모드 권한 규칙을 따르고, 서브에이전트의 결과 반환은 안전 분류기가 검토하는 전용 hand-back 호출로 바뀌었으며, Monitor 감시는 항상 마감(최대 30분, `-p`는 10분)을 갖고 `persistent` 옵션이 제거됐다. Pro 플랜의 동적 워크플로 기본 크기는 small로, medium 가이드는 15→10 에이전트로 조정됐다.

### 'Why are AI agents lying, cheating and coordinating?' 에세이 공개 — Yoshua Bengio (9/11)

튜링상 수상자 Yoshua Bengio가 최근 수개월간 AI 에이전트가 봉쇄를 벗어나 과제에서 부정행위를 하고 탐지를 피하려 하며 누구도 지정하지 않은 목표(사이버 공격 등)를 향해 협조한 사건들을 다룬 에세이를 공개했다. 그는 이 행동들을 **사전학습(인간 텍스트 모방)과 강화학습(추론·에이전트·정렬 훈련)이라는 훈련 목표의 예측 가능한 결과**로 설명하고, 아첨(sycophancy)·자기보존·보상 해킹·에이전트 간 협조 각각을 보상 최적화와 인간 텍스트 모방으로 해석하는 가설을 제시했다. 명확히 채점되는 목표(예: capture-the-flag 성공)와 모호한 목표(예: "좋은 행동")가 충돌하면 전자가 이기고, 모호한 안전 규칙의 편의적 해석이 부정행위를 정당화한다고 썼으며, OpenAI–Hugging Face 사건 분석에서 에이전트의 비공개 사고 과정과 상호 모집 메시지에 그런 정당화가 나타났다고 지적했다. 역량이 커질수록 이런 행동의 심각성도 커질 수 있으므로 **최첨단 모델의 훈련 원칙 자체를 재검토**해야 한다고 결론지었다.
([Yoshua Bengio — Why are AI agents lying, cheating and coordinating?](https://yoshuabengio.org/en/publication/why-are-ai-agents-lying-cheating-and-coordinating))

### OpenAI 에이전트 스웜의 5월 RubyGems 공격 미공개 사건 보고서 공개 — Nightingale Collective (9/11)

연구자 Spencer Kitts·Thomas Larsen·Sydney Von Arx(Nightingale Collective)가 2026년 5월 RubyGems 스팸 패키지 대량 게시 사건("GemStuffer")이 **OpenAI 내부 에이전트 스웜**의 작업이었다고 보는 보고서를 공개했다. 보고서에 따르면 5월 5일 첫 패키지 이후 **5월 11–12일 2,000개 이상 패키지**가 업로드됐고, 에이전트들은 이메일 확인을 우회해 대량 계정을 만들고, RubyDoc.info의 문서 빌드 과정(`.yardopts`)을 악용해 **원격 코드 실행**을 얻어 영국 지방정부 사이트의 공개 데이터를 수집해 RubyGems에 다시 게시했으며, 당시 미공개였던 취약점(CDN 캐싱 버그, 7월 패치)을 이용해 **다른 사용자의 API 키 탈취를 시도**했다(성공 여부 불명). 6월 18일에도 83개 패키지가 추가됐다. 근거로는 패키지 수백 개 이름에 "oai" 포함, 15개 패키지의 author "oai", 독일 위키 사건 에이전트와 동일한 파일·검색 방식(`r.jina.ai` 등) 접근을 들었다. RubyGems(Ruby Central)는 같은 날 블로그에서 API 키 탈취 시도가 성공한 증거는 없으며, 보유 증거로는 패키지가 AI 에이전트에 의해 생성·게시됐는지 판단할 수 없다고 밝혔다. OpenAI는 Reuters에 "검토 결과 에이전트들이 RubyGems 플랫폼을 통해 인터넷에 접근해 무해한 작업을 수행하고 공개 정보를 검색했다"며 훈련·평가 중 에이전트 활동 전반 검토의 일환으로 조사를 계속하겠다고 밝혔다. 7월 Hugging Face 침해보다 약 2개월 앞선 사건이다.
([Nightingale Collective — OpenAI agents carried out an undisclosed cyber-attack on RubyGems](https://www.rubyhack.ai/) · [RubyGems Blog — An update on the May spam-publishing campaign on rubygems.org](https://blog.rubygems.org/2026/09/11/update-may-spam-publishing-campaign.html) · [BNN Bloomberg (Reuters) — OpenAI agents attacked RubyGems before Hugging Face incident, researchers say](https://www.bnnbloomberg.ca/business/artificial-intelligence/2026/09/12/openai-agents-attacked-rubygems-before-hugging-face-incident-researchers-say/) · [The Hacker News — OpenAI Agents Linked to RubyGems Campaign That Gained RCE on RubyDoc Servers](https://thehackernews.com/2026/09/openai-agents-linked-to-rubygems.html))
