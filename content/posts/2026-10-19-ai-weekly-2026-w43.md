## 🧠 모델 출시

### MiniMax M3.1 Flash 출시, 에이전트 작업 사용 비용 이전 모델 대비 70% 절감 주장 — MiniMax (10/19)
MiniMax가 경량 모델 **MiniMax M3.1 Flash**를 공개하고 MiniMax API·M Plan·MiniMax Code로 제공을 시작했다. 회사는 온라인 추론이 **약 3배 빨라졌고** 에이전트 작업의 전체 사용 비용이 이전 모델보다 **70% 낮다**고 밝혔으며, 가격은 100만 토큰당 **입력 0.15달러·출력 0.60달러·캐시 입력 0.015달러** 정액이다. 모델 가중치는 "추후 공개"한다고 했다(날짜 미정).
출처: [MiniMax — MiniMax M3.1 Flash: Redefining Agent Performance and Cost](https://www.minimax.io/blog/minimax-m31f) · [SiliconANGLE — MiniMax launches M3.1 Flash model, says it cuts AI agent costs by 70%](https://siliconangle.com/2026/10/19/minimax-launches-m3-1-flash-model-says-it-cuts-ai-agent-costs-by-70/)

### Mercury 3 출시, 초당 1,000토큰 이상 생성하는 확산(diffusion) LLM·컨텍스트 100만 토큰 — Inception Labs (10/19)
Inception이 확산 기반 언어 모델 **Mercury 3**를 출시했다. NVIDIA GPU에서 **초당 1,068토큰**을 생성하고 컨텍스트는 Mercury 2.5의 26만 토큰에서 **100만 토큰**으로 늘었으며, 가격은 100만 토큰당 입력 0.20달러·출력 0.70달러(출시 기념 50% 할인 적용 시 0.10·0.35달러)다. Inception API·OpenRouter·Baseten·Vercel에서 OpenAI API 호환으로 제공되며, 회사는 GPT-6 Luna·Claude Haiku 5.5보다 4~8배 빠르다고 주장했다.
출처: [Inception — Diffusion at Scale: Introducing Mercury 3](https://www.inceptionlabs.ai/blog/introducing-mercury-3)

### Clairic 공개, 출력 토큰 없이 단일 순전파로 값을 추출·예측하는 모델(프리뷰) — Cloudflare (10/19)
Cloudflare가 새 'System One' 계열의 첫 추출 모델 **Clairic**을 Workers AI에 프리뷰(`@cf/cloudflare/clairic`)로 공개했다. 비정형 입력에서 값을 추출·계산·추정·예측하며, 출력 토큰을 생성하지 않고 **입력 토큰만 한 번의 순전파**로 처리해 요청 필드가 3개든 30개든 비용이 거의 같다. 회사 측 보험금 청구 파이프라인 테스트에서 LLM만 쓴 구성보다 **약 3.2배 빠르고 49% 저렴**했다고 밝혔으며, 오픈 웨이트로도 공개할 예정이다(날짜 미정).
출처: [Cloudflare Blog — Introducing Clairic, a new System One class of extraction models](https://blog.cloudflare.com/clairic-extraction-model/)

### Maxwell 공개, 실행 중인 프로그램의 기계어를 다시 쓰는 '코드 실행 모델' — doubleAI (10/19)
Amnon Shashua가 이끄는 doubleAI가 첫 제품 **Maxwell**을 공개하고 얼리 액세스를 열었다. 소스 코드는 그대로 둔 채 실행 중인 프로그램을 관찰해 하드웨어·데이터에 맞게 **기계어를 재작성**하며(CPU·GPU 지원), 각 변경이 프로그램 동작을 바꾸지 않음을 형식적으로 증명하고 전제 조건이 깨지면 원래 코드로 되돌린다고 회사는 설명했다. 회사 발표 기준 데이터 파이프라인은 38배 이상, AI 추론 커널은 4.5배 이상 빨라졌으며, 고객이 절감한 컴퓨트 비용의 일부를 받는 방식으로 과금한다.
출처: [The Next Web — Amnon Shashua's doubleAI launches an AI that speeds up code while it runs](https://thenextweb.com/news/doubleai-maxwell-code-execution-model-compute-costs) · [Ctech(Calcalist) — Shashua's doubleAI unveils AI models that optimize how software runs](https://www.calcalistech.com/ctechnews/article/sk11xpc73ge)

## 🤖 AI 코딩 에이전트

### OpenCode Console 레거시 시스템 무단 접근 공개, 저장된 OpenAI·Anthropic 등 제공사 API 키 노출 가능성 — OpenCode (10/17)
오픈소스 코딩 에이전트 OpenCode가 폐기 중이던 **레거시 시스템에 대한 무단 접근**을 확인했으며, 호스팅 서비스 **OpenCode Console** 워크스페이스에 저장된 OpenAI·Anthropic 등 **서드파티 제공사 API 키가 노출됐을 수 있다**고 공지했다. 회사는 이번 사고를 "대규모 증류(distillation) 공격"과 관련된 것으로 설명하며 Console 사용자의 **약 1.4%**가 영향을 받았고, 해당 사용자 전원에게 이메일로 통보했다(메일을 받지 않았다면 영향 없음)고 밝혔다. 영향받은 사용자에게는 각 제공사에서 키를 폐기·교체하도록 안내했다.
출처: [OpenCode (X) — 보안 사고 공지](https://x.com/opencode/status/2111519637049319818) · [OfficeChai — OpenCode Discloses Security Breach, Says Attackers May Have Accessed Users' OpenAI, Anthropic And Google API Keys](https://officechai.com/ai/opencode-discloses-security-breach-says-attackers-may-have-accessed-users-openai-anthropic-and-google-api-keys/)

### Claude Code 2.1.304: `/auto-mode-setup`·`/claude-api managed-agents-secure`·Code Review 리뷰 수준 선택 — Anthropic (10/19)
Anthropic이 Claude Code **2.1.304**를 배포했다. 프로젝트와 최근 세션을 읽어 auto mode에 사용 환경을 알려 주는 가이드 설정 **`/auto-mode-setup`**이 추가돼 Bedrock·Vertex·Foundry에서도 쓸 수 있고, **`/claude-api managed-agents-secure`**는 Managed Agents 에이전트 설정을 Anthropic이 공개한 보안 가이드와 비교한다(설정은 바꾸지 않음). Pro·Max 요금제에서 오래 쉬던 대화를 재개할 때 5시간 사용 한도를 눈에 띄게 쓰게 되면 경고하고, Code Review에는 조직 단위 **Quick·Standard·Deep 리뷰 수준**과 GitHub 조직의 모든 저장소를 리뷰하는 옵션이 생겼다. HEAD가 분리된 상태 등에서 `claude --worktree`가 종료 시 묻지 않고 워크트리와 브랜치를 지워 커밋을 잃을 수 있던 버그도 고쳤다.
출처: [GitHub — anthropics/claude-code Release v2.1.304](https://github.com/anthropics/claude-code/releases/tag/v2.1.304)

### Copilot 모델 정책 REST API 정식 제공, 엔터프라이즈·조직·팀 단위 모델 허용 관리 — GitHub (10/19)
GitHub가 Copilot에서 쓸 수 있는 모델을 관리하는 **모델 정책 REST API**를 정식(GA) 제공했다. 엔터프라이즈·엔터프라이즈 팀·엔터프라이즈 앱·조직 4개 수준에 GET·PATCH 엔드포인트(예: `/enterprises/{enterprise}/copilot/model-policies`)가 있으며, 엔터프라이즈 정책에서 모델 통제권을 조직 또는 팀·앱 단위로 넘길 수 있다.
출처: [GitHub Changelog — Copilot model policy API for enterprise, orgs, and teams](https://github.blog/changelog/2026-10-19-copilot-model-policy-api-for-enterprise-orgs-and-teams)

### Copilot에서 GPT-5.5·GPT-5.4·Gemini 3.7 Flash·Grok 4.5 등 6개 모델 지원 종료 — GitHub (10/19)
GitHub가 9월 18일 예고한 대로 Copilot Chat·인라인 편집·ask/agent 모드·코드 완성 등 대부분의 Copilot 환경에서 **GPT-5.5·GPT-5.4·GPT-5.4 mini·GPT-5 mini·Gemini 3.7 Flash·Grok 4.5**를 지원 종료했다. 권장 대체 모델은 GPT-6.1 Sol(GPT-5.5·5.4 대체), GPT-6 Luna(5.4 mini·5 mini 대체), Gemini 3.8 Flash, Grok 4.7이며, 기업 관리자는 필요하면 Copilot 모델 정책에서 대체 모델을 활성화해야 한다.

## 🛠️ 도구 · 벤치마크

### 저자원 프로그래밍 언어 코딩 평가 공개, SQLite 구현 벤치마크 MultiLangBench 오픈소스화 — OpenAI (10/19)
OpenAI가 COBOL·OCaml·Fortran 같은 저자원(low-resource) 프로그래밍 언어에서의 코딩 성능 개선을 다룬 글을 게시하고 소프트웨어 엔지니어링·SQLite·COBOL 마이그레이션 평가를 소개했다. 함께 공개한 벤치마크 **MultiLangBench**(Apache 2.0)는 모델이 문서만 보고 지정 언어로 **SQLite 3.40.1 호환 실행 파일**을 구현하게 한 뒤 SQLite TCL 테스트에서 변환한 테스트로 채점하며, 요청한 언어로 작성하지 않으면 통과율을 0으로 처리한다. 보도에 따르면 OpenAI가 밝힌 언어 평균 점수는 GPT-6 Astra **87.4%**, GPT-5.6 Sol 26.8%다.
출처: [OpenAI — Advancing coding in low-resource programming languages](https://openai.com/index/low-resource-programming-languages/) · [GitHub — openai/MultiLangBench](https://github.com/openai/MultiLangBench) · [AlphaSignal — OpenAI's GPT-6 Astra Cracks COBOL, Scoring 72% on Banking's Ancient Code](https://alphasignal.ai/news/openai-s-gpt-6-astra-cracks-cobol-scoring-72-on-banking-s-ancient-code)

### TorchNeuron 발표, AWS Trainium용 네이티브 PyTorch 백엔드 오픈소스·10/20 퍼블릭 베타 — AWS (10/19)
AWS가 PyTorch 블로그에서 Trainium을 표준 PyTorch 디바이스로 쓰게 하는 오픈소스 네이티브 백엔드 **TorchNeuron**을 발표했다. PyTorch의 PrivateUse1 확장점으로 Trainium2·Trainium3를 등록해 `.to('neuron')`만으로 기존 코드를 돌리고, eager 실행·`torch.compile`·FSDP2 등 분산 API·커스텀 커널용 NKI를 지원한다. **Apache 2.0**으로 `aws-neuron/torch-neuronx` 저장소에 공개되며, 10월 20일 PyTorch Conference North America에 맞춰 **퍼블릭 베타**(`pip install torch-neuronx`)로 제공된다.
출처: [PyTorch Blog — Introducing TorchNeuron: Native PyTorch backend for AWS Trainium](https://pytorch.org/blog/introducing-torchneuron-native-pytorch-backend-for-aws-trainium/)

### 영국 Essex Loughton 데이터센터 계약 철회 보도, 전력망 연결 2030년대로 지연 — Microsoft · Nscale (10/18)
영국 Telegraph는 Microsoft가 AI 클라우드 Nscale의 **Essex Loughton 데이터센터** 계약을 해지했다고 보도했다. 이 부지는 Nvidia 칩 약 **2만 3,000개**를 둘 예정이었으며, 전력망 당국이 **2030년대 전까지 전력 공급을 예상하지 않는다**고 Nscale에 전하면서 개소 시점이 당초 목표였던 2027년에서 밀렸다는 내용이다. Nscale은 Reuters에 Microsoft와의 관계는 "여전히 견고하고 장기적"이며 런던 전역의 전력망 문제는 다른 계약에 영향이 없고 대체 전력원을 검토 중이라고 밝혔다. Microsoft는 논평을 거절했다.

### 기가와트급 슈퍼클러스터 Prometheus 내부 공개, Muse Wonder 사전학습 굿풋 85% 이상 — Meta (10/19)
Meta가 엔지니어링 블로그에서 오하이오주 New Albany의 AI 슈퍼클러스터 **Prometheus**를 상세히 공개했다. 1단계가 완료돼 여러 건물에 걸친 **수십만 개 GPU**로 Muse Wonder 등 Muse 모델을 학습했고, 최종적으로 약 **100만 GPU**를 목표로 한다. 건물 단위 이더넷 패브릭 하나가 최대 20,736개 GPU를 연결하며, Muse Wonder 학습에서 사전학습 **85% 이상**·강화학습 **90% 이상**의 굿풋(goodput)을 기록했다고 밝혔다.
출처: [Engineering at Meta — Inside Prometheus: Meta's Journey to a Gigawatt-Scale Supercluster](https://engineering.fb.com/2026/10/19/data-center-engineering/inside-prometheus-meta-gigawatt-scale-supercluster/)

### 에이전트 샌드박스에 NVIDIA Vera CPU 도입 계획, 밀집 부하에서 Intel 대비 최대 2배 처리 — Modal · NVIDIA (10/19)

Modal 자체 테스트(코딩 작업 50개)에서 컨테이너를 빽빽이 채운 조건일 때 Vera가 Intel 서버보다 **최대 2배** 많은 작업을 처리했고, 단일 작업에서는 우위가 작고 일정하지 않았다. Intel·AMD 프로세서도 함께 계속 쓰며, 고객 제공 시점은 밝히지 않았다.
